# M0 — Fundação Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deixar o monorepo pronto para desenvolver funcionalidades: `pnpm dev` sobe API, worker e web; `pnpm test` roda; o CI bloqueia PR quebrado; dinheiro e datas têm funções testadas.

**Architecture:** Monorepo pnpm + Turborepo. `packages/core` (domínio puro, sem I/O) e `packages/contracts` (schemas Zod) são compilados com `tsup` para `dist/` e consumidos por `apps/api` (NestJS + Prisma + pg-boss, um processo que sobe em modo `api` ou `worker`) e `apps/web` (React + Vite). Testes de integração da API usam PostgreSQL real via Testcontainers.

**Tech Stack:** Node 24 LTS, pnpm 10 (via corepack), Turborepo, TypeScript strict, Vitest, NestJS 11 (builder SWC), Prisma 7 (`prisma.config.ts` + `@prisma/adapter-pg`), Zod 4 + `nestjs-zod`, `@nestjs/swagger`, `nestjs-pino`, pg-boss, React 19, Vite, Tailwind CSS 4, shadcn/ui, TanStack Router/Query, Testcontainers, GitHub Actions.

**Spec:** [docs/fases/M0-fundacao.md](../../fases/M0-fundacao.md), com [ARQUITETURA.md](../../ARQUITETURA.md), [ADR-0001](../../decisoes/0001-stack-e-monorepo.md), [ADR-0003](../../decisoes/0003-dinheiro-e-datas.md) e [ADR-0005](../../decisoes/0005-jobs-pg-boss.md).

## Global Constraints

- Node fixado em `.nvmrc` = `24` e `"engines": { "node": ">=24 <25" }`; pnpm fixado em `packageManager` (rodar `corepack enable` e `corepack use pnpm@latest-10`).
- TypeScript `strict: true` em todos os pacotes; nada de `any` implícito.
- Escopo de pacotes: `@nx-balance/core`, `@nx-balance/contracts`, `@nx-balance/config`, `@nx-balance/api`, `@nx-balance/web`.
- Dependências: `apps/*` → `packages/contracts` → `packages/core`. O `core` não importa nada do projeto nem módulos de I/O do Node. Nenhum app importa de outro app.
- Dinheiro: inteiro em centavos (`number`, seguro até `Number.MAX_SAFE_INTEGER`); proibido `float` e `toFixed` em cálculo de dinheiro.
- Datas de competência: string `AAAA-MM-DD`; fuso padrão `America/Sao_Paulo`; `month_start_day` de 1 a 28.
- Erros da API sempre no formato `{ code, message, details? }`; mensagens em português.
- API versionada com prefixo `/v1`; OpenAPI em `/docs` (JSON em `/docs-json`).
- Fim de linha LF em todo o repositório (`.gitattributes`: `* text=auto eol=lf`).
- Commits em Conventional Commits (o commitlint passa a exigir a partir da Task 1).
- Cobertura de `packages/core` acima de 95% (linhas, branches, funções e statements).

**Convenção decidida neste plano (não está na spec):** o mês financeiro recebe o nome do mês em que **começa**. Com `month_start_day = 5`, o mês `2026-09` vai de 2026-09-05 a 2026-10-04.

## Review Focus

1. `parseBRL` com o que as pessoas digitam: `"1.234,56"`, `"1234,56"`, `"R$ 10"`, `" 10,5 "` são aceitos; `"10.5"`, `"10,555"`, `"1,2,3"`, `""` e `"abc"` são rejeitados com erro, nunca viram outro valor em silêncio (teste na Task 2).
2. Valores acima de `Number.MAX_SAFE_INTEGER` centavos: soma, subtração e parse lançam `RangeError` em vez de perder precisão (teste na Task 2).
3. "Hoje" perto da meia-noite: `2026-09-28T01:30:00Z` ainda é `2026-09-27` em São Paulo (teste na Task 3).
4. Virada de ano no mês financeiro: `2026-01-03` com início no dia 5 pertence ao mês `2025-12` (teste na Task 3).
5. Banco fora do ar: `GET /v1/health` responde `503` com `database: "down"` rapidamente, sem derrubar o processo nem vazar stack (teste na Task 6).
